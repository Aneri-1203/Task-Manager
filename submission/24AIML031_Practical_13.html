Practical 13: AI API Integration into a Web Application

Practical Statement

  • Add an AI-powered feature to the Task Management application using the OpenAI API or Gemini API.
  • The feature must serve a meaningful purpose — for example, auto-generating a task description, suggesting a priority level, or proposing a deadline based on the task title.
  • The API key must be stored and used only on the backend (.env), never exposed to the frontend.
  • Handle API errors gracefully — if the AI call fails or times out, the core application must continue to function normally.
  • Display the AI-generated response meaningfully in the React UI, not as raw JSON.

1. Feature Implemented: AI Task Description Generator

The implemented feature is an AI Task Description Generator integrated into the task creation form. When the user enters a task title, they can click the "✨ Generate Description" button to receive a concise, context-aware, single-paragraph description generated by the Google Gemini API (gemini-2.5-flash model).

Why This Feature?

Writing meaningful task descriptions is time-consuming. The AI feature helps users quickly fill in the description field with relevant, actionable content based solely on the task title, improving productivity without replacing the user's judgment. The user can review and edit the suggestion before saving.

3. Backend Implementation

Route: routes/aiRoutes.js

const express = require("express");
const router = express.Router();
const { generateDescription } = require("../controllers/aiController");
const authMiddleware = require("../middleware/authMiddleware");
const { aiRateLimiter } = require("../middleware/aiRateLimiter");

// POST /api/ai/generate-description
// Protected by JWT authentication and rate limiter
router.post("/generate-description", authMiddleware, aiRateLimiter, generateDescription);

module.exports = router;

Controller: controllers/aiController.js

const { generateTaskDescription } = require("../services/aiService");

const generateDescription = async (req, res, next) => {
    const { title } = req.body || {};

    // Input Validation
    if (!title || typeof title !== "string") {
        return res.status(400).json({ success: false, message: "Title is required." });
    }
    const trimmedTitle = title.trim();
    if (trimmedTitle.length < 3) {
        return res.status(400).json({ success: false, message: "Title must be at least 3 characters." });
    }

    // Call AI service (handles live Gemini and demo mode)
    const result = await generateTaskDescription(trimmedTitle);

    if (!result.success) {
        return res.status(result.statusCode || 503).json({
            success: false, fallback: true,
            errorCategory: result.errorCategory,
            message: result.message,
        });
    }

    return res.status(200).json({
        success: true,
        description: result.description,
        demo: result.demo || false,
        source: result.source || "gemini",
    });
};
module.exports = { generateDescription };

4. Security: API Key Never Exposed to Frontend

The GEMINI_API_KEY is stored exclusively in the backend .env file. The React frontend never receives, stores, or transmits the key. All AI calls are proxied through the Express backend endpoint POST /api/ai/generate-description, which authenticates the user via JWT before processing. The .env file is listed in .gitignore and is never committed to the repository.

AI API Failure Handling

When the AI provider is unavailable (invalid key, network error, etc.), the backend returns a structured fallback response. The frontend displays a yellow warning banner with a human-readable message. The task creation form itself remains fully functional — users can type the description manually.

AI API Rate Limit Handling

The backend enforces a 60-second per-user-per-title cooldown using SHA-256 hashed keys in an in-memory Map. When a user requests the same title within 60 seconds, the backend returns HTTP 429 with a remainingSeconds field. The frontend countdown timer ticks down in real time, changing the button label to "Wait 59s" and re-enabling it automatically when the cooldown expires.

Key Questions

1. Why must the AI API key be called from the backend rather than directly from the React frontend?

The AI API key should be stored and used in the backend because frontend code is visible to users. If the key is placed in React code, anyone can access it using browser developer tools and misuse the account — incurring costs or exhausting quotas. The backend keeps the key secret in a .env file that is never committed to the repository and never sent to the client. It also allows secure control over API requests, input validation, rate limiting, and error handling before any call reaches the external provider.

2. What does 'graceful degradation' mean in this context, and why does it matter for a feature that depends on a third-party service outside your control?

Graceful degradation means the application continues to work correctly even when the AI service is unavailable or fails. Instead of crashing or blocking the user, the backend returns a clean fallback response with a user-friendly error message, and the task creation form remains fully functional. The user can still create tasks manually. It matters for third-party services because their availability, quotas, and pricing are outside the developer's control — a quota limit, billing issue, or network outage must not break the core product.

3. What are the privacy and governance implications of sending task data to an external AI API, and what kind of data should never be sent this way?

Sending task data to an external AI API may expose confidential information and create privacy risks. Developers should follow data protection policies, obtain appropriate user consent, and check the provider's data-handling rules. In this implementation, only the task title (not the full task object, user ID, or any personal data) is sent to the Gemini API. Passwords, API keys, financial details, personal identification information, medical records, and confidential business data should never be sent to external AI APIs without proper authorization, anonymization, and legal safeguards.
